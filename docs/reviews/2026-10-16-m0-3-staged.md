## 3. Findings
### BLOCKER
none

### HIGH
1. **Spike test spawns `node <file>.ts`, which fails on the Node 20 CI leg** — `scripts/spike-scan.test.mjs:51`
   - Problem: fact: `run()` calls `execFileSync('node', [SCRIPT, ...])` where `SCRIPT` is `scripts/spike-scan.ts`, and the script's own usage line (`scripts/spike-scan.ts:3`) is `node scripts/spike-scan.ts`. Fact: `vitest.config.ts` includes `scripts/**/*.test.mjs`, so this test runs in `npm test`; `.github/workflows/ci.yml` runs `npm run test:coverage` on a matrix `node: [20, 22, 24]`; root `package.json` declares `engines.node >=20`. Judgement (from Node release history, not run in this session): Node 20 has no TypeScript type stripping, so `node x.ts` fails with `ERR_UNKNOWN_FILE_EXTENSION` and both `M0.3:` tests fail on that leg. The local run was on Node 24.6.0 (`docs/benchmark.md:14`), which hides this.
   - Why it matters: CLAUDE.md "Commands" says Node >= 20; a red CI leg on the supported minimum is a real defect the local pre-flight cannot catch.
   - Fix: skip the spike tests below the first Node version with unflagged type stripping (e.g. `describe.skipIf(!process.features.typescript)`), or run the script through a loader that exists on all matrix versions, and state the Node requirement in the script header and `docs/benchmark.md` step 2.
