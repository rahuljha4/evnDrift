# ED003 — unused-declaration

**Requirement:** FR-RULE-ED003

| Item | Value |
|---|---|
| Milestone | M1.5 (rule), M3 (J3 demo) |
| Source | [PRD §11](../../prd.md#11-rules), [ADR 0003](../../architecture/adr/0003-dynamic-access-downgrades-unused.md) |
| Explain text | [`rules.md`](../../rules.md) |

## Summary
A variable is declared in `.env.example` or in an environment, but no scanned code reads it. It is a candidate for removal.

## Fires when
A declaration in `.env.example` or any environment has no reference.

This finding is **downgraded to `info` with a note if any ED005 exists (D3)**, unless `--strict` is given.

| Property | Value |
|---|---|
| Default severity | `warning` |
| Locations reported | The declaration (source file and line) |
| `environments` | The environment owning the source. Not set for the example. |

## Grouping
There is one finding per (name, source), so J3 can list unused declarations per source.

## Message template
`<NAME> is declared in <source path> but no references found in <N> scanned files`

Here `N` is `stats.filesScanned`.

## Fix template
`Remove <NAME> from <source path>, or reference it in code`

## D3 note
When downgraded, the finding gets:

`note: "downgraded to info: the scan found <K> dynamic env accesses, so unused cannot be proven (use --strict to disable)"`

## Examples

**Fires**
```dotenv
# .env.example
LEGACY_REDIS_URL=
```
No code reads `LEGACY_REDIS_URL`. The result is `ED003 warning LEGACY_REDIS_URL .env.example:2`.

**Downgraded (D3)**
The same setup, but `src/config.ts` contains `process.env[key]`. The result is `ED003 info … note: downgraded…`.

**Does not fire**
- Any reference exists, including references that have a fallback.
- The name is in the merged ignore list (e.g. `PATH`, `npm_*`).
- The only reference is in an excluded test file. In that case ED003 **does** fire, by design ([ADR 0002](../../architecture/adr/0002-exclude-test-files-by-default.md)).

## Interactions

| Aspect | Behaviour |
|---|---|
| D3 | Triggered by any dynamic access in the model. `--strict` disables it. |
| Config override | `rules.ED003: error` applies **before** D3. D3 still downgrades to `info` unless `--strict` is given ([severity-resolution.md](../severity-resolution.md)). |
| Suppression | `# envdrift-ignore ED003` on the line above the key in dotenv or keys files |
| `--env` | Environment declarations are only checked for the selected environments. The example is always checked. |
| `fix --prune` | Uses the same "unused" computation |
| ED007 tracked files | Not checked. They are not configured sources. |

> **Open question:** do suppressed ED005 accesses, or `rules.ED005: off`, still trigger D3? *Proposal:*
> - Suppressed accesses **do not** count. Suppressing a dynamic access asserts that it is harmless.
> - `rules.ED005: off` does **not** stop D3. "Off" only hides the report; the uncertainty remains.

> **Open question:** do declarations from Dockerfile `ARG`, and SSM parameters that the infrastructure needs but the app never reads, cause noise? *Proposal:* yes. They are handled via `ignore` or suppression, and this is documented in the README limitations.

## Required tests (`packages/core/test/rules/ED003.test.ts`)
1. **Positive:** `ED003 fires per unused declaration per source with the scanned-file count`.
2. **Negative:** `ED003 does not fire for referenced or ignored names`.
3. **Suppression:** `ED003 is dropped by '# envdrift-ignore ED003' above the key`.
4. **D3:** `ED003 is info with note when dynamic access exists, and warning under --strict`.

The fixture `dynamic-heavy` covers D3 end to end.
