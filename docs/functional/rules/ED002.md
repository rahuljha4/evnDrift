# ED002 — missing-in-env

**Requirement:** FR-RULE-ED002

| Item | Value |
|---|---|
| Milestone | M1.5 |
| Source | [PRD §11](../../prd.md#11-rules) |
| Explain text | [`rules.md`](../../rules.md) |

## Summary
Code reads a variable without a fallback, and an environment does not declare it. The app will crash or misbehave after deploy. This is EnvDrift's headline check.

## Fires when
For environment E, both of these hold:
- A referenced name is absent from **all** of E's sources.
- **At least one reference has no fallback.**

| Property | Value |
|---|---|
| Default severity | `error` |
| Locations reported | The references **without** a fallback |
| `environments` | The environments where the name is missing (sorted) |

## Grouping
There is one finding per name. All environments where the name is missing are listed in `environments`.

> **Open question:** should ED002 produce one finding per name, or one per (name, environment)? *Proposal:* one per name, with `environments` sorted. This matches the fingerprint formula, which includes `environments`, and keeps PR comments compact.

## Message template
`<NAME> is read without a fallback but missing in: <env1>, <env2>`

## Fix template
`Add <NAME> to <env1> (<first source path>), <env2> (…)`

## Examples

**Fires**
```ts
// src/api/webhook.ts
const secret = process.env.PAYMENTS_WEBHOOK_SECRET;
```
- `production` has sources `Dockerfile` and SSM `/myapp/prod/`. Neither declares `PAYMENTS_WEBHOOK_SECRET`.
- Result: `ED002 error PAYMENTS_WEBHOOK_SECRET src/api/webhook.ts:2 [production]`

**Does not fire**
- Any source of `production` declares the name. A declaration with `hasValue: false` still counts as declared.
- Every reference has a fallback (`process.env.X ?? 'dev'`). ED009 fires instead ([ADR 0005](../../architecture/adr/0005-fallback-missing-is-ed009.md)).
- No environments are configured.

## Interactions

| Aspect | Behaviour |
|---|---|
| D5 | Mixed references (some with a fallback, some without) give ED002, reporting only the references without one |
| `--env` | Only the selected environments are checked |
| Ignore | Names in the merged ignore list never fire |
| Suppression | Per reference location. Same semantics as ED001. |
| D3 | Not affected |

## Required tests (`packages/core/test/rules/ED002.test.ts`)
1. **Positive:** `ED002 fires per missing environment and reports only non-fallback references`.
2. **Negative:** `ED002 does not fire when declared in any source of E, or when every reference has a fallback`.
3. **Suppression:** `ED002 is dropped when every non-fallback reference carries envdrift-ignore ED002`.
