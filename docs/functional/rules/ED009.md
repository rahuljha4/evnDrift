# ED009 — default-masks-missing

**Requirement:** FR-RULE-ED009

| Item | Value |
|---|---|
| Milestone | M1.5 |
| Source | [PRD §11](../../prd.md#11-rules), [ADR 0005](../../architecture/adr/0005-fallback-missing-is-ed009.md) |
| Explain text | [`rules.md`](../../rules.md) |

## Summary
Code reads a variable with a fallback, and an environment does not declare it. The app will not crash, but it silently runs on the code's development default, for example `http://localhost:3000` in production.

## Fires when
For environment E, both of these hold:
- A referenced name is absent from E.
- **Every reference has a fallback.**

| Property | Value |
|---|---|
| Default severity | `warning` |
| Locations reported | The references |
| `environments` | The environments where the name is missing (sorted) |

## Grouping
There is one finding per name. This matches ED002.

## Mutual exclusion with ED002
For a given name and environment, exactly one of ED002 or ED009 can fire:

| References | Rule |
|---|---|
| At least one without a fallback | ED002 |
| All with a fallback | ED009 |

## Message template
`<NAME> is missing in <envs>; code will silently use its fallback default`

## Fix template
`Add <NAME> to <envs>, or remove the fallback if the variable is required`

## Examples

**Fires**
```ts
const api = process.env.API_BASE_URL ?? 'http://localhost:4000';
```
`production` does not declare `API_BASE_URL`, so the result is `ED009 warning API_BASE_URL src/api.ts:1 [production]`.

**Does not fire**
- `production` declares `API_BASE_URL`.
- One reference lacks a fallback, so ED002 fires instead.
- The name is ignored.

## Interactions

| Aspect | Behaviour |
|---|---|
| Fallback forms | See the F rows in [`patterns-catalogue.md`](../../patterns-catalogue.md), and the accessor second-argument and `??`/`||` forms |
| Config | Teams that treat silent defaults as release blockers set `rules.ED009: error` (see the [configuration example](../configuration.md#full-example)) |
| `--env` | Only the selected environments are checked |
| Suppression | Per reference location, like ED002 |

## Required tests (`packages/core/test/rules/ED009.test.ts`)
1. **Positive:** `ED009 fires when every reference has a fallback and E lacks the name`.
2. **Negative:** `ED009 does not fire when any reference lacks a fallback (ED002 instead) or the name is declared`.
3. **Suppression:** `ED009 is dropped when every reference carries envdrift-ignore ED009`.
